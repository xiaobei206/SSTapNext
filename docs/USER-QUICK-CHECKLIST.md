# 用户验收速查（只做必须由你本人完成的部分）

代码、依赖、配置批量检查、Agent 编译和安装包由 Harness 一次性处理。你不需要亲自读源码，也不需要把节点凭据交给 Harness。

## 你只做这 4 件事

1. **把本项目目录交给 Harness**，直接粘贴 `HARNESS-ONE-SHOT-AUDIT.md` 里的整段任务。让它一次性跑完 Windows 构建和自动化审查，最后必须给出安装包、SHA-256 和完整测试报告。不要让它连接你的真实节点或启动真实 TUN。
2. **安装 Harness 构建出的安装包**。打开 SSTap Next，确认你以前能正常导入的单节点、多节点和订阅仍在；如果数据没有自动迁移，不要删除旧版数据文件，先告诉 Harness。
3. **测试本地代理**。选择一条你确认可用的节点，连接本地代理，在浏览器临时填入软件显示的 `127.0.0.1` SOCKS5 地址，打开网页并运行测速；完成后断开，确认普通浏览器恢复直连。
4. **测试无路由网卡 smoke test**。运行 `scripts\Run-Tun-SmokeTest.ps1` 并批准 UAC。它只创建并删除测试网卡，不接管默认路由或 DNS。连续通过两次，再考虑真实系统接管。

## 以下由你本人决定，不能让 Harness 自动批准

- 第一次真实 TUN 会接管系统 IPv4/IPv6 路由和 DNS。只有本地代理、无路由 smoke test 都通过，并准备好手机热点/备用上网方式后再做。
- 测试时确认出口 IP、网页、DNS、UDP/QUIC；断开后网卡消失且网络恢复。
- 真实 TUN 的详细检查项目见 `WINDOWS-ACCEPTANCE.md`。出现 `cleanup_error`、网卡残留、DNS/路由异常时立即停止，不要重复点击连接。

## 给 Harness 的材料

可以提供：构建日志、测试报告、脱敏后的 sing-box 日志、网络快照。不要提供：节点 URI、密码、订阅 URL、`state.enc.json`。日志中如含节点服务器地址，先自行检查再决定是否发送。
