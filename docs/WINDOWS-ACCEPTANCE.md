# SSTap Next 0.3.7 — Windows 10/11 实机验收清单

目标：在一次有记录的验收中确认应用、核心、测速、IPv4/IPv6 DNS、TUN 和断开清理正常。**先做普通代理与无路由 smoke test，全部通过后才接管系统路由。** 首次真实 TUN 测试请准备手机热点或其他备用联网方式。

## A. 构建、安装与 UI

- [ ] 从 `SSTapNext_0.3.7` 源码目录运行 `scripts\Build-Windows.ps1`，完整流程退出码 0。
- [ ] `[2/8]` Node 测试全部通过；当前源码基线为 67 项，实际数字以输出为准。
- [ ] `[3/8]` 当前 sing-box 核心通过 54 份协议/模式/DNS 地址族配置检查。
- [ ] `[4/8]` .NET 10 win-x64 自包含 Agent 发布成功。
- [ ] `[5/8]` TypeScript 与 Vite 正式构建成功。
- [ ] `[6/8]` 生成 `release\SSTap Next-0.3.7-x64.exe`。
- [ ] 安装并启动，版本显示 0.3.7；主按钮在已选节点、无其他任务且本地代理已断开的前提下呈蓝色可用状态，悬停/按下/键盘焦点有反馈。
- [ ] 如果主按钮禁用，按钮下方应显示原因；检查是否未选节点、本地代理仍连接、核心未找到或存在 `cleanup_error`。
- [ ] 检查节点、订阅、测速、设置页字号；常规说明文本不应小于 14px。

## B. 本地代理与测速

- [ ] 选择一条已知有效的节点，连接本地代理。
- [ ] 首页显示 loopback SOCKS5 / HTTP 地址，手工浏览器代理能够访问预期网站。
- [ ] 运行延迟/下载测速，确认请求经本地 SOCKS5 节点，而不是绕过代理。
- [ ] 若测速主源返回 HTTP 403，应在进度提示中看到正在切换备用源；最终结果的“测试源”显示实际使用的 Hetzner 镜像域名。
- [ ] 测速不能成功时记录最终失败的源与状态码；不要把单个测试镜像 403 当成节点故障。
- [ ] 点击断开，本地代理退出后未配置代理的浏览器仍可正常直连。

## C. DNS 地址族与内核管理

- [ ] 软件设置中默认应是 `IPv4 only`；升级后用户旧设置保持不变。
- [ ] TUN 未启动时，可分别保存 IPv4-only、双栈 IPv4 优先、双栈 IPv6 优先；TUN 运行期间选择器禁用。
- [ ] 核对 `sing-box` 当前实际版本、可执行路径；点击“打开内核目录”能打开真实目录。
- [ ] 依照 `docs\CORE-UPGRADE.md` 做手动核心升级演练前先备份；本次不必真的升级核心。
- [ ] 若手动放入新核心后重新构建，构建脚本应使用当前核心版本检查 54 份配置，失败时停止打包。

## D. Wintun 无路由 smoke test

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\Run-Tun-SmokeTest.ps1
```

- [ ] UAC 后测试启动；此 smoke config 明确不接管默认路由与 DNS。
- [ ] 输出 PASS，临时测试网卡创建后成功移除。
- [ ] 前后 IPv4/IPv6 默认路由、物理网卡路由和 DNS 快照一致。
- [ ] 连续执行两次均通过。

若接口未移除、路由/DNS 变化或出现 FAIL：停止，不要启动真实 TUN。

## E. 第一次真实 TUN

- [ ] 本地代理及 smoke test 全部通过，备用网络可用。
- [ ] 先以 IPv4-only 策略、已验证节点启动全局 TUN；确认 UAC、Agent、sing-box、TUN 接口都进入 running/Up。
- [ ] 使用 ZeroOmega Direct，浏览器应由系统 TUN 接管；检查 IPv4 出口变为节点出口。
- [ ] IPv4-only 模式下域名解析不应为应用提供 IPv6 地址；系统 IPv6 路由仍保留在 TUN 内，不允许物理网络直连泄漏。
- [ ] 若网络和节点出口都具备公网 IPv6，断开 TUN 后将 DNS 策略切换为双栈 IPv4 优先或 IPv6 优先，再重连分别验证。
- [ ] 双栈 IPv6 测试必须独立验证 `curl.exe -6` 的 TLS、公网出口以及浏览器 IPv6 访问；不能仅凭路由器 WAN 获得 IPv6 判断代理支持。
- [ ] 访问 YouTube、Google 等实际浏览器页面并播放视频；单独 `curl -4` 的 HTTP 200/204 只代表 IPv4 HTTP 端点可达，不能替代浏览器业务测试。
- [ ] 断开 TUN，检查 Agent 的优雅停止、核心退出和网卡清理记录；再次连接/断开，确认不会产生 `cleanup_error`。
- [ ] 至少重复 10 轮“开启 TUN → 正常断开 → 再次连接”。每轮若 Windows 保留 `Description=sing-tun Tunnel ...` 的网卡对象，但 `Status=Down` 且 `Addresses=[]`（不含 `172.19.0.1`），应视为 Wintun 会话已释放；程序不应因该设备对象仍存在而报 `cleanup_error`。
- [ ] 负向保护：若接口仍为 `Up` 或仍持有 `172.19.0.1`，必须继续报 `cleanup_error` 并阻止再次接管；不得通过删除网卡绕过。

## F. 立即停止条件

以下任一情况发生，停止 TUN 测试，不要再次点击连接，也不要手动删除不明网卡或重置 Windows 网络：

- 状态为 `cleanup_error`；
- `SSTap Next` 网卡仍存在且状态/资源归属不明确；
- 物理网卡 DNS、默认路由与连接前基线不一致；
- IPv4/IPv6 流量出现非预期物理网卡直连；
- UAC 取消或 Agent 启动失败后仍有 sing-box 进程或虚拟网卡。

日志分享前检查并脱敏节点服务器地址；不要公开节点 URI、密码、订阅地址或 `state.enc.json`。
